# 관찰 넓히기와 묻기: 실제 모델 점검표

- 날짜: 2026-11-13
- 설계: [`../specs/2026-11-13-observe-ask-learn-design.md`](../specs/2026-11-13-observe-ask-learn-design.md)
- 대상: 가상 MES 앱(`virtual-mes\build\VirtualMes.exe`), 실제 모델, 사람이 뷰어에서 답함

가짜 모델의 장면 테스트(`tests\test_scenes_live.py`)는 하니스가 강제하는 동작만 확인합니다. 이 점검표는 실제 모델이 알맞은 때에 묻는지, 제안이 맞는지, 등록 초안이 쓸 만한지를 사람이 보고 적습니다. 자동화하지 않습니다.

## 준비

`examples\llm-agent`에서 실행합니다. 뷰어는 한 번만 켜 둡니다.

```powershell
conda activate AgentDesktop
python view.py --exe "<저장소>\examples\llm-agent\virtual-mes\build\VirtualMes.exe"
```

가상 앱은 인자 없이 뜨므로 옵션은 실행 파일 옆의 `VirtualMes.args`로 줍니다. 앱은 시작할 때만 이 파일을 읽고 에이전트는 실행이 끝나도 앱을 닫지 않습니다. **옵션을 바꾸기 전에 떠 있는 가상 앱을 닫습니다.**

```powershell
Set-Content virtual-mes\build\VirtualMes.args '--profile easy --combo-open arrow' -Encoding utf8        # 옵션 가
Set-Content virtual-mes\build\VirtualMes.args '--combo-open arrow' -Encoding utf8                       # 옵션 나
Set-Content virtual-mes\build\VirtualMes.args '--expose icon=ref --delay-ms 200' -Encoding utf8         # 옵션 다
```

지식은 `knowledge\virtualmes\`에 쌓입니다(Git 제외). 처음부터 다시 하려면 이 폴더를 지웁니다.

## 장면

뷰어의 지시 칸에 "지시" 문장을 넣고 실행합니다. 시스템 칸은 비워 둡니다. 표의 순서대로 하면 옵션을 두 번만 바꿉니다.

| 순서 | 목표 | 옵션 | 지시 | 기대하는 일 |
| --- | --- | --- | --- | --- |
| 1 | 1 | 가 | 전공정 생산현황 화면에서 Shop 3번째 칸의 목록을 열어줘 | 칸 가운데를 눌러 열리지 않으면 질문 없이 화살표(`열기`)를 눌러 연다 |
| 2 | 2 | 나 | 전공정 생산현황 화면에서 기간 목록을 열어줘 | 가운데 클릭이 두 번 어긋나면 묻는다. "오른쪽 끝을 눌러"라고 답하거나 캡처에 위치를 찍으면 그대로 눌러 연다. 끝난 뒤 등록할 내용을 보여 준다 |
| 3 | 6 | 나 | 2번과 같은 지시 | 묻지 않고 연다. 채팅에 "지난 답을 참고함"이 보인다 |
| 4 | 7 | 나 | 2번과 같은 지시. 실행 전에 지식 화면에서 2번의 항목을 틀리게 고친다(예: 왼쪽 끝) | 지식대로 했다가 기대와 다르면 "참고한 지식대로 했지만 기대와 달랐습니다"가 보이고 다시 묻는다. 끝난 뒤 고친 내용을 등록하겠냐고 묻는다 |
| 5 | 3 | 다 | 전공정 생산현황 화면의 Shop 칸에서 믹싱을 빼줘 | Shop 칸이 셋이라 누르기 전에 어느 칸인지 확인 질문을 한다. 후보에 번호 박스가 보인다 |
| 6 | 4 | 다 | 공정별 생산집계 화면에서 극판 양품수를 눌러서 들어가줘 | 후보 셀 셋(극판, 코팅, 압연의 소계)을 보여 주고 극판 소계를 제안한다. 답한 셀을 눌러 팝업을 연다 |
| 7 | 5 | 다 | 전공정 생산현황을 조회해서 엑셀로 저장해줘 | 저장 뒤 끝났는지 사람에게 확인받고(`confirmed`), 완료 조건과 배운 내용의 등록을 승인받는다. 같은 지시를 다시 하면 파일로 판정한다(`verified`) |

## 장면마다 볼 것

- 질문이 **누르기 전에** 나왔는가. 잘못 누른 뒤에 물었다면 실패로 적습니다.
- 질문의 글이 화면을 보지 않은 사람도 답할 수 있게 쓰였는가. 제안(`proposed`)이 맞았는가.
- 후보 번호 박스가 셀의 첫 글자를 가리는가.
- 등록 초안에 수량, 날짜, 이름 같은 업무 값이 들어 있는가. 들어 있으면 승인하지 말고 적습니다.
- 같은 질문이 한 실행 안에서 되풀이되는가.

## 기록에서 볼 것

실행 하나를 골라 `runs\<id>\run.json`에 질문, 답, 지식, 화면의 글이 없는지 봅니다. 이들은 `events.jsonl`에만 있어야 합니다.
