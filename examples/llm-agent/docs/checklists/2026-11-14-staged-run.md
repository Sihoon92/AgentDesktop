# 단계로 나눠 실행하기: 실제 모델 점검표

- 날짜: 2026-11-14
- 설계: [`../specs/2026-11-14-staged-run-design.md`](../specs/2026-11-14-staged-run-design.md)
- 계획: [`../plans/2026-11-14-staged-run.md`](../plans/2026-11-14-staged-run.md)의 작업 6
- 대상: 가상 MES 앱(`virtual-mes\build\VirtualMes.exe`), 실제 모델, 사람이 뷰어에서 답함

가짜 모델의 테스트는 하니스가 강제하는 것만 확인합니다. 실제 모델이 단계를 알맞게 나누는지, 줄인 기록을 API가 받는지, 한도가 알맞은지는 이 점검표로 사람이 보고 적습니다. 실제 창을 띄우고 커서를 움직이며 토큰을 쓰므로, 돌리기 전에 PC를 쓰는 사람에게 확인받습니다.

## 준비

`examples\llm-agent`에서 실행합니다. 가상 앱은 옵션 없이(기본 프로파일) 띄웁니다. 떠 있는 가상 앱이 있으면 먼저 닫습니다.

```powershell
conda activate AgentDesktop
Remove-Item virtual-mes\build\VirtualMes.args -ErrorAction SilentlyContinue
python view.py --exe "<저장소>\examples\llm-agent\virtual-mes\build\VirtualMes.exe"
```

지식은 `knowledge\virtualmes\`에 쌓입니다(Git 제외). 4번 장면의 앞뒤를 비교하려면 시작 전에 이 폴더의 상태를 적어 둡니다.

## 실행마다 적을 것

실행이 끝나면 요약(`python view.py --summary latest`)에서 다음을 옮겨 적습니다.

- 판정, 스텝, 토큰
- `단계:` 줄(단계 수, 완료 수, 단계별 호출, 한도 질문, 계획 고침)
- `호출당 토큰 최대:`. 지난 실행의 16번째 호출은 20,779토큰이었습니다. 절반(10,390) 이하인지 봅니다
- `동작:` 줄의 불일치와 "확인 못 함" 수

## 따로 볼 것

- **API가 줄인 기록을 받는가.** 400 오류로 멈추면 오류 코드와 몇 번째 스텝인지 적습니다. 도구 호출과 결과의 짝이나 추론 항목의 자리를 문제 삼는 오류라면 `agent/history.py`의 규칙을 다시 봐야 합니다.
- **단계 한도 8이 알맞은가.** 정당하게 긴 단계(목록에서 여러 항목을 고르는 단계 등)가 한도에 걸리는지, 걸렸다면 그 단계를 모델이 둘로 나눴어야 했는지 적습니다.
- **모델이 계획을 세우지 않는 경우.** 앱을 바꾸는 호출이 `needs_plan`으로 거절된 수를 요약의 `거절:` 줄에서 봅니다.
- **체크 해제의 판정.** 목록의 체크를 푸는 동작이 "확인 못 함"으로 나오고, 모델이 캡처를 보고 다음으로 가는지. 연달아 눌러 막히지 않는지.
- **기록.** `runs\<id>\run.json`에 단계의 글(목표, 완료 기준, 메모)이 없는지 봅니다. `events.jsonl`에만 있어야 합니다.

## 실제 창 테스트 (대본 모델, 2026-11-15)

실제 모델 없이 대본대로 움직이는 모델로 실제 창을 띄워 확인했습니다(`VIRTUAL_MES_LIVE=1`, `tests/test_virtual_mes_live.py`와 `tests/test_scenes_live.py`, 71개). 토큰은 쓰지 않습니다.

| 결과 | 수 | 내용 |
| --- | --- | --- |
| 통과 | 63 | 첫 실행에서 통과 |
| 다시 돌려 통과 | 2 | 원형 메뉴 테스트 둘. 실행 중 다른 창이 포커스를 가져가 메뉴가 닫힌 것으로 보입니다 |
| 테스트를 고쳐 통과 | 4 | 합성 캡처 둘(표시 상자가 그려진 캡처를 원본과 비교함), 체크 해제의 판정 하나(첫 클릭에서 포커스가 목록으로 옮겨 가는 것을 변화 없음으로 단정함), 화살표 테스트 하나(요소 id를 잘못 적음). 제품 코드는 고치지 않았습니다 |
| 판정을 고쳐 통과 | 2 | `test_scene_2_...`, `test_scene_6_...`. 아래 "정한 것" |

확인된 것: 열린 목록 창이 캡처와 프레임에 들어감(표시 상자를 뺀 일치 99.7%), 목록 안을 눌러도 관찰이 주 창에 남음, 체크 해제가 "확인 못 함"으로 나오고 막히지 않음, 화살표로만 열리는 칸의 동작.

**정한 것(사용자 결정, 2026-11-15).** 기간 칸의 가운데를 누르면 목록은 열리지 않지만 칸 주변의 그림이 60픽셀 바뀝니다(포커스 표시). 기대가 `window_opened`인데도 판정이 "기대와 다른 결과"가 아니라 "확인 못 함"이 되어 연속 횟수에 들어가지 않았고, 그래서 두 번 실패한 뒤 사람에게 묻게 하는 규칙이 걸리지 않았습니다. 창이 열렸는지는 창 목록으로 알 수 있으므로, `window_opened`와 `window_closed`는 그림을 보지 않고 판정하도록 고쳤습니다(`agent/screen_tools.py`). 고친 뒤 `tests/test_scenes_live.py` 12개가 실제 창에서 모두 통과했고, 장면 2는 원래 대본대로(불일치 두 번, 세 번째 거절, 막힘 질문, 답대로 눌러 성공) 갑니다.

## 회사에서 확인할 것

- 사내 API가 줄인 기록의 형식을 받는지(위 "API가 줄인 기록을 받는가"와 같은 방법).
- 사내 모델이 `plan`과 `stage_done`을 부르는지, 계획 전 호출의 추론 노력(`plan_reasoning_effort: medium`)을 받는지.
- 실제 MES의 화면에서 단계 한도 8이 알맞은지. 요약의 `단계:` 줄만 전하면 됩니다.
