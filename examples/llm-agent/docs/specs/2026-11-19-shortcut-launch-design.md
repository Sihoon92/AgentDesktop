# 바로가기(.lnk)로 대상 앱 띄우기

- 날짜: 2026-11-19
- 상태: 방법은 사용자가 고름(2026-11-19, "1번으로 진행해"). 구현 끝, 가상 MES의 실제 창에서 확인함(인자와 시작 위치가 든 바로가기로 점검, workflow 재실행, 등록 화면). 회사의 실제 바로가기로는 아직 돌리지 않음
- 대상: `examples/llm-agent`의 CLI 클라이언트(`agent/desktop.py`), 새 모듈 `agent/shortcut.py`, 점검(`check.py`). `agent-desktop` CLI는 고치지 않습니다.
- 앞선 설계: [시스템 골라 띄우고 준비될 때까지 기다리기](2026-11-18-system-launch-ready-design.md), [시스템 프로파일](2026-11-19-system-profile-design.md)

## 왜 하는가

회사의 GSCM은 exe를 직접 실행하지 않고, 정해진 폴더에 나눠 둔 바로가기(`.lnk`)로 실행합니다. 지금은 `systems`나 `--exe`에 `.lnk`를 적으면 띄우지 못합니다.

```
CreateProcessW failed to start the application (0x800700C1)
```

`agent-desktop launch`는 Windows의 `CreateProcess`로 프로그램을 시작하고, `CreateProcess`는 실행 파일만 시작합니다. 바로가기는 실행 파일이 아니라 "어느 exe를, 어떤 인자로, 어느 폴더에서 시작하라"를 적은 파일이고, 그것을 풀어 주는 것은 탐색기입니다. 바로가기의 대상 exe를 직접 적는 것으로는 부족합니다. 바로가기에 적힌 인자와 시작 위치를 하니스가 CLI에 넘기지 않기 때문입니다.

## 목표와 하지 않는 것

**목표**

- exe 경로를 적는 모든 곳에 `.lnk` 경로를 적을 수 있습니다: `run.py --exe`, 설정의 `systems`와 `exe`, 작업 파일의 `exe`, 뷰어의 실행 설정, 등록 화면, `check.py`.
- 바로가기에 적힌 대상, 인자, 시작 위치 그대로 띄웁니다.
- 띄운 뒤의 동작은 exe를 적었을 때와 같습니다: 준비 기다리기, "이미 떠 있음" 판정, 다시 띄우기(`restart_target`), workflow 재실행.
- 띄우지 못하면 앱을 건드리기 전에 코드로 알립니다.

**하지 않는 것**

- 대상이 exe가 아닌 바로가기(배치 파일, 웹 주소, 스토어 앱, 제어판 항목)는 띄우지 않습니다. 회사의 바로가기가 이런 것으로 드러나면 그때 "탐색기처럼 열기"를 더합니다(아래 방법 2).
- "관리자 권한으로 실행", 창 크기(최소화·최대화), 단축키 같은 바로가기의 다른 설정은 따르지 않습니다.
- 폴더를 주면 그 안의 바로가기를 모두 시스템으로 올리는 기능은 만들지 않습니다. 시스템은 지금처럼 `systems`에 한 줄씩 적습니다.

**실패로 보는 것**

- 인자나 시작 위치가 빠진 채 대상만 띄움(다른 사이트로 붙거나 설정을 못 찾는 앱이 됨).
- 바로가기의 대상, 인자, 시작 위치가 요약, `check.py` 출력, `run.json`에 나옴.

## 방법 비교 (사용자가 고름)

1. **하니스가 바로가기를 풀어서 띄우기 (고름).** 대상, 인자, 시작 위치를 읽어 `agent-desktop launch <대상> --arg=<인자>… --cwd <시작 위치>`로 넘깁니다. CLI가 띄운 프로세스를 지금처럼 돌려주므로 그 뒤의 것이 바뀌지 않습니다.
2. **탐색기처럼 열기.** 무엇이든 열리지만 띄운 프로세스를 돌려받지 못해 "새로 뜬 창"으로 대상을 짐작해야 하고, 이미 떠 있는지 알기 어렵습니다.
3. **CLI(Rust)가 `.lnk`를 받게 하기.** 맞는 층이지만 Rust 수정과 CI 확인이 필요합니다.

## 동작

- **바꾸는 자리는 하나입니다.** 하니스의 모든 띄우기는 CLI 클라이언트(`DesktopClient`)의 `launch` 명령을 거칩니다(준비 기다리기, 모델의 `launch_target`과 `restart_target`, 등록 화면, 점검). 클라이언트가 `launch`의 대상이 `.lnk`로 끝나면(대소문자 무시) 바로가기를 읽어 명령을 바꿔 보냅니다. 띄우기를 부르는 쪽은 고치지 않습니다.
- **띄울 때마다 읽습니다.** 실행 중에 바로가기가 바뀌어도 다음 띄우기에 반영되고, 따로 기억해 둘 것이 없습니다.
- **이름과 비교는 `.lnk` 경로로 합니다.** 설정의 `systems`와 견주는 경로, 기록의 `exe`, 시스템 이름의 기본값(파일 이름)은 사용자가 적은 `.lnk` 경로 그대로입니다. 대상 exe의 경로는 어디에도 남기지 않습니다.
- **읽는 방법:** Windows 셸의 바로가기 읽기(`IShellLinkW`)를 표준 라이브러리 `ctypes`로 부릅니다. 탐색기가 쓰는 것과 같은 것이라 네트워크 경로, 환경 변수가 든 경로, 한글 경로를 따로 다루지 않아도 됩니다. 새 의존성이 없고, PowerShell을 띄우지 않습니다(회사 PC의 정책으로 막힐 수 있음).
- **인자:** 바로가기의 인자는 글 한 줄입니다. Windows의 규칙(`CommandLineToArgvW`)으로 나눠 하나씩 `--arg=<값>`으로 넘깁니다. 인자가 없으면 넘기지 않습니다.
- **시작 위치:** 환경 변수를 풀어 `--cwd`로 넘깁니다. 비어 있으면 넘기지 않습니다(exe를 직접 띄울 때와 같음).

## 띄우지 못할 때

바로가기를 읽는 데서 막히면 CLI를 부르지 않고, CLI의 실패와 같은 꼴로 답합니다. 그래서 부르는 쪽은 지금의 "띄우기 실패" 처리 그대로입니다(준비 기다리기는 `launch_failed`, 점검은 `실패(코드)`).

| 코드 | 뜻 |
| --- | --- |
| `SHORTCUT_UNREADABLE` | 바로가기 파일을 읽지 못함(없음, 깨짐, Windows가 아님) |
| `SHORTCUT_NO_TARGET` | 대상 경로가 없음(스토어 앱, 제어판 항목 등) |
| `SHORTCUT_NOT_EXE` | 대상이 `.exe`가 아님 |
| `SHORTCUT_TARGET_MISSING` | 대상 exe 파일이 없음 |

알리는 글은 정해진 문구이고 경로나 인자를 넣지 않습니다.


## 알려진 한계

- **같은 exe에 인자만 다른 바로가기 여럿:** 하나가 떠 있는 동안 다른 것을 실행하면 "같은 시스템이 이미 떠 있습니다"로 멈춥니다. CLI가 같은 exe의 떠 있는 프로세스에 붙기 때문입니다. 잘못된 창을 조작하지는 않습니다.
- **인자의 따옴표:** 인자를 나눴다가 CLI가 다시 묶으므로, 명령줄 전체를 글자 그대로 읽는 앱은 따옴표 위치가 달라 보일 수 있습니다. 보통의 앱(인자를 나눠 받는 앱)에는 차이가 없습니다.
- **관리자 권한이 필요한 대상:** 지금의 exe와 같이 CLI의 띄우기가 실패합니다.

## 설계자가 정한 것 (사용자가 말한 것이 아님)

1. 바꾸는 자리는 CLI 클라이언트 하나이고, 띄울 때마다 바로가기를 읽습니다.
2. 바로가기는 `ctypes`로 Windows 셸에 물어 읽습니다. PowerShell이나 새 패키지를 쓰지 않습니다.
3. 시작 위치가 비었으면 `--cwd`를 넘기지 않습니다.
4. 대상이 `.exe`일 때만 띄웁니다.
5. 실패 코드 넷과 `check.py`의 `바로가기:` 줄.
6. 이름과 비교는 `.lnk` 경로로 하고, 대상의 경로·인자·시작 위치는 출력과 기록에 넣지 않습니다.

## 구현자에게 맡기는 것

- 모듈과 함수의 이름, 읽는 함수를 클라이언트에 넣는 방법(테스트에서는 가짜로 바꿀 수 있어야 함).
- `ctypes`로 읽는 것이 이 PC에서 안 되면 알립니다. 그때는 바로가기 파일 형식을 직접 읽는 방법으로 바꿉니다.

## 확인이 필요한 것

1. **회사 GSCM 바로가기의 대상이 `.exe`인지.** `check.py`의 `바로가기:` 줄로 압니다. `SHORTCUT_NOT_EXE`나 `SHORTCUT_NO_TARGET`이 나오면 방법 2를 더합니다.
2. **바로가기들이 같은 exe를 가리키는지.** 그렇다면 한 번에 하나만 띄울 수 있습니다(알려진 한계).

## 시험과 확인

- 읽기: 테스트가 임시 폴더에 실제 바로가기를 만들어(대상, 인자, 시작 위치, 한글과 공백이 든 경로) 읽은 값을 봅니다. 창을 띄우지 않습니다.
- 클라이언트: 가짜 runner로 `launch <x.lnk>`가 어떤 명령으로 나가는지, 실패 코드마다 CLI를 부르지 않는지, `.lnk`가 아닌 대상은 지금과 같은지 봅니다.
- 목표와 "실패로 보는 것"의 항목마다, 어겼을 때 실패하는 테스트가 적어도 하나 있습니다.
- **실제 창 확인:** 인자가 든 바로가기로 가상 MES를 띄워 `check.py`, 모델 없는 재실행, 등록 화면의 "앱 띄우기"가 되는지 봅니다. 인자가 실제로 전해졌는지는 가상 MES의 자체 기록으로 확인합니다.
