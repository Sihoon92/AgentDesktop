# 가상 MES 앱 설계

- 날짜: 2026-11-12
- 상태: 구현됨(2026-11-13). 완료 기준 2와 5의 손 확인(사용자가 직접 조작)은 아직 하지 않았습니다. 사용법은 [`../../virtual-mes/README.md`](../../virtual-mes/README.md), 구현 계획은 [`../plans/2026-11-12-virtual-mes-app.md`](../plans/2026-11-12-virtual-mes-app.md)
- 배경: [`../cua-background.md`](../cua-background.md)
- 화면 목업: https://claude.ai/artifact/TDgXkvJedGxY1wnNyLwESf (소유자만 열 수 있음)

## 왜 만드는가

회사 MES는 집 PC에서 실행할 수 없고, 회사에서 찍은 스냅샷과 스크린샷도 집으로 가져올 수 없습니다. 그래서 CUA의 공통 기능(관찰 넓히기, 사람에게 묻기, 실패에서 배우기, workflow 생성)을 집에서 개발하고 시험할 대상이 필요합니다.

가상 MES 앱은 그 대상입니다. 사용자가 기억으로 설명한 MES 화면과 조작 흐름을 재현하고, 에이전트가 헤맬 장면을 **일부러, 되풀이해서** 만들어 냅니다. 이 앱이 쉬우면 쓸모가 없습니다.

이 문서는 가상 앱만 다룹니다. 에이전트 쪽 변경은 이 앱이 생긴 뒤 따로 설계합니다. 순서는 (1) 가상 앱, (2) 관찰 넓히기와 사람에게 묻기, (3) 실패에서 스킬·가이드라인 남기기, (4) workflow 생성입니다.

## 목표

1. 배경 문서의 "MES 화면 (사용자 설명)"에 적힌 흐름을 모두 손으로 조작할 수 있다.
2. 같은 화면을 **노출 방식**만 바꿔 다시 띄울 수 있다. 노출 방식은 컨트롤이 접근성 트리에 어떻게 보이는지를 뜻한다(아래 "노출 방식").
3. 에이전트가 무엇을 했는지 화면 밖의 기록으로 확인할 수 있다. 하니스는 앱이 쓴 이벤트 기록과 저장된 엑셀 파일로 성공을 판정한다.
4. 같은 옵션으로 띄우면 같은 화면, 같은 데이터, 같은 대기 시간이 나온다.
5. 새 설치 없이 빌드된다. 회사 PC에서도 같은 방법으로 빌드할 수 있다.

## 하지 않는 것

- MES 업무 시뮬레이션. 로그인, 서버, DB, 실제 데이터, 권한은 없습니다.
- 에이전트 코드 변경. 글자로 요소 찾기, OCR, 스킬 저장 등은 다음 설계입니다.
- 브라우저 앱 재현. 브라우저 일반화는 상용 브라우저로 시험합니다.
- 실제 MES와 같은 모양. 배치와 동작이 맞으면 되고 색과 글꼴은 맞추지 않습니다.
- CI 편입. `ci.yml`은 건드리지 않습니다.

## 이렇게 되면 실패

- 기본 설정에서 대부분의 컨트롤에 ref가 붙어, 지금 에이전트가 손대지 않고도 통과한다.
- 에이전트 실행 코드에 이 앱의 이름, 창 제목, 화면 배치를 가정한 분기가 들어간다(`AGENTS.md`의 application-agnostic 규칙). 이 앱의 이름은 작업 파일과 테스트에만 나옵니다.
- 에이전트가 이벤트 기록을 읽어 정답을 안다. 기록은 하니스만 읽습니다.
- 실행할 때마다 데이터나 대기 시간이 달라져 실패를 재현할 수 없다.

## 제약

- **빌드:** 기존 픽스처(`tests/fixture-app-windows`)와 같은 방식입니다. C# WinForms 소스를 Windows에 들어 있는 .NET Framework 4.x 컴파일러(`%WINDIR%\Microsoft.NET\Framework64\v4.0.30319\csc.exe`, `/langversion:5`)로 컴파일하는 `build.ps1`을 둡니다. NuGet 패키지와 SDK 설치는 쓰지 않습니다.
- **위치:** `examples/llm-agent/virtual-mes/`. 실행 파일 이름은 `VirtualMes.exe`, 창 제목은 `MES (가상)`입니다. 빌드 출력 폴더는 Git에서 제외합니다.
- **DPI:** 이 PC는 175% 배율입니다. 앱은 시스템 DPI를 인식하도록 선언해 접근성 트리의 좌표가 물리 픽셀과 맞게 하고, 창이 작아져도 "조회(F5)" 버튼이 보이도록 배치합니다.
- **다른 프로그램을 띄우지 않습니다.** "열기"를 눌러도 엑셀을 실행하지 않습니다.
- **Rust 규칙 대상이 아닙니다.** 주석 금지, 400줄 제한 같은 저장소 규칙은 `crates/**`와 `src/**`에만 적용됩니다.

## 화면

메뉴바 카테고리는 5개(기준정보, 생산운영, 품질관리, 설비관리, 자재관리)이고, 동작하는 것은 "생산운영"뿐입니다. 나머지는 빈 목록 창을 띄웁니다.

"생산운영" 글자를 클릭하면 목록 창이 뜨고 항목 5개가 나옵니다.

| 목록 항목 | 화면 | 엑셀 아이콘 | 용도 |
| --- | --- | --- | --- |
| 전공정 생산현황 | 조회 화면 A | 있음 | 기본 흐름, 아이콘 저장 |
| 권취 Roller 점검일시 | 조회 화면 B | 없음 | 3칸 필터 다중 선택, 우클릭 저장 |
| 공정별 불량현황 | 표 화면 C | 없음 | 셀 클릭 팝업, 팝업 안 우클릭 저장 |
| 후공정 생산현황 | 빈 화면 | 없음 | "전공정"과 헷갈리는 이름 |
| 설비 가동현황 | 빈 화면 | 없음 | 관계없는 항목 |

화면을 고르면 목록 창이 닫히고 그 화면으로 바뀝니다. 화면은 한 번에 하나만 열립니다(설계자 판단: 실제 MES가 여러 탭을 여는지는 모릅니다).

모든 화면의 구성은 같습니다: 왼쪽 필터 열, 왼쪽 아래 "조회(F5)" 버튼, 오른쪽 데이터 패널, 아래 상태 줄. 조회 전에는 데이터 패널이 비어 있습니다.

### 배치

목업은 소유자만 열 수 있으므로, 맞춰야 하는 배치를 여기에 적습니다.

- **위에서 아래로:** 제목 줄, 메뉴바(카테고리 5개가 가로로), 현재 화면 이름 탭, 본문, 상태 줄.
- **목록 창:** 클릭한 카테고리 바로 아래에 뜨고, 위에 카테고리 이름이 있는 제목 줄, 그 아래 항목이 세로로 나열됩니다.
- **필터 열:** 필터마다 이름이 위, 박스가 아래입니다. Shop의 3칸은 가로 한 줄입니다. 날짜 입력 칸 2개는 기간 박스 바로 아래에 `~`를 사이에 두고 가로 한 줄입니다. "조회(F5)" 버튼은 필터 열의 맨 아래입니다.
- **드롭다운 목록:** 그 박스 바로 아래에 뜹니다. 다중 선택 목록은 맨 위 한 줄에 "All", "Select" 버튼이 가로로 있고 그 아래 행이 세로로 나열됩니다.
- **데이터 패널:** 맨 위 한 줄의 왼쪽에 화면 이름, 오른쪽 끝에 엑셀 아이콘(화면 A만). 그 아래가 표입니다.
- **원형 메뉴:** 우클릭한 지점이 원의 중심입니다. 1단계에서 "export"는 위쪽 칸입니다. 2단계에서 "excel"은 오른쪽 위, "html"은 아래, "pdf"는 왼쪽 위 칸입니다.
- **셀 팝업:** 본 창 위에 뜨는 제목 줄 있는 창이며, 제목에 고른 행과 열 이름이 들어갑니다.

### 뜨는 것들의 창 구조

메뉴 목록 창, 드롭다운 목록, 다중 선택 목록, 원형 메뉴, 로딩 팝업, 셀 팝업, "저장 | 열기 | 취소" 팝업은 모두 본 창과 별개의 최상위 창입니다(설계자 판단: WinForms를 비롯한 대부분의 툴킷이 이렇게 띄웁니다. 실제 MES의 구조는 모릅니다). 그래서 `pixel` 방식이어도 "창이 하나 생겼다"는 것과 그 창의 위치·크기는 창 목록에서 보이고, 안의 내용만 보이지 않습니다.

창 제목은 내용을 드러내지 않게 `메뉴 목록`, `목록`, `메뉴`로 둡니다. 이 창들은 클릭해도 활성 창이 되지 않지만, 자동화 도구가 좌표 클릭 전에 활성 창으로 만들 수 있습니다. 그래서 활성 창이 팝업이나 그 소유 창인 동안에는 닫지 않고, 다른 앱으로 넘어가면 닫습니다.

목록이나 원형 메뉴 밖을 클릭하면 그 클릭은 닫는 데만 쓰이고 아래 컨트롤에는 전달되지 않습니다(설계자 판단). 예를 들어 Shop 목록이 열린 채 "조회(F5)"를 클릭하면 목록만 닫히고, 조회하려면 한 번 더 클릭해야 합니다.

### 필터

| 화면 | 필터 |
| --- | --- |
| A 전공정 생산현황 | Shop(3칸 모두 활성), 공정, 제품, 기간 |
| B 권취 Roller 점검일시 | Shop(1·2번 칸 비활성, 3번 칸만 활성), 설비, 기간 |
| C 공정별 불량현황 | 제품, 기간 |

- **단일 선택 드롭다운(공정, 제품, 설비):** 박스를 클릭하면 항목 목록이 뜨고, 항목을 클릭하면 닫히며 값이 바뀝니다.
- **기간:** 항목은 "전일", "전전일", "전주", "기간"입니다. "기간"을 고르면 아래의 날짜 입력 칸 2개(`YYYY-MM-DD` ~ `YYYY-MM-DD`)가 활성화되고, 다른 항목을 고르면 다시 비활성화됩니다. 필터 이름 "기간"과 항목 "기간"은 같은 글자이며, 이 중복은 의도한 것입니다.
- **Shop 3칸:** 칸마다 다중 선택 목록입니다(설계자 판단: 사용자가 확인한 것은 3번 칸뿐이며, 세 칸에 같은 컨트롤을 씁니다). 칸을 클릭하면 목록이 뜹니다.
  - 맨 위에 "All", "Select" 버튼이 가로로 있습니다. "All"은 모든 행을 체크하고, "Select"는 체크한 상태를 적용하며 목록을 닫습니다.
  - 그 아래는 `체크박스 | 코드 | 이름` 행입니다. 3번 칸의 행은 `WA0`~`WA3` 4개이고, 화면 A에서 사용자가 "조립"으로 고를 수 있도록 이름 하나에는 "조립"이 들어갑니다. 나머지 이름과 1·2번 칸의 행은 빌더가 정합니다.
  - 목록 밖(왼쪽 열이나 빈 곳)을 클릭해도 체크한 상태 그대로 적용되며 닫힙니다.
  - 닫힌 칸에는 선택 결과가 표시됩니다(전부면 "전체", 하나면 그 이름, 여럿이면 개수, 없으면 "선택 없음"). 처음에는 모든 행이 체크되어 있습니다.
  - 비활성 칸은 클릭해도 열리지 않습니다.

### 조회

"조회(F5)" 버튼을 클릭하거나 F5 키를 누르면 조회합니다. 회전하는 이미지와 안내 글이 있는 팝업 창이 뜨고, 대기 시간이 지나면 팝업이 닫히며 데이터 패널이 채워집니다. 대기 중에는 본 창을 조작할 수 없습니다. ref로 하는 조작도 막히고, 그동안 본 창의 요소는 비활성으로 보입니다.

대기 시간은 기본이 1~4초 사이에서 조회마다 달라지고, 같은 시드면 같은 순서로 나옵니다. `--delay-ms`로 고정할 수 있습니다.

데이터는 앱에 들어 있는 고정 표에서 필터 값으로 걸러 냅니다. 같은 필터면 항상 같은 행이 나옵니다. 앱의 "오늘"은 `2026-11-12`로 고정이라 "전일"은 언제 실행해도 `2026-11-11`입니다. 구체적인 값은 구현 계획의 "고정 데이터"에 있습니다. 조회 화면 A와 B의 결과는 날짜·Shop·공정 등의 열을 가진 행 목록이고, 표 화면 C의 결과는 행이 믹싱/극판/조립/화성, 열이 생산수/불량수/불량률인 표입니다.

### 엑셀 저장 1: 아이콘

화면 A의 데이터 패널 오른쪽 위에 작은 엑셀 아이콘이 있습니다. 클릭하면 "저장 | 열기 | 취소" 팝업이 뜹니다.

- "저장": 저장 경로 창이 뜹니다. Windows 표준 저장 대화상자를 씁니다(설계자 판단: 목업은 단순한 창으로 그렸지만, 표준 대화상자가 실제 앱에 가깝고 다른 앱에도 통하는 시험이 됩니다).
- "열기": 임시 폴더에 파일을 쓰고 이벤트 기록에 남깁니다. 엑셀은 실행하지 않습니다.
- "취소": 닫습니다.

조회 전에 아이콘을 누르면 "조회된 데이터가 없습니다" 알림 창이 뜹니다(설계자 판단).

### 엑셀 저장 2: 우클릭 원형 메뉴

데이터 패널 아무 곳이나 우클릭하면 그 위치에 원형 메뉴가 뜹니다.

- 1단계: 4등분 원. 위 칸이 "export"이고 나머지 세 칸은 "copy", "print", "close"입니다(실제 MES의 이름은 모릅니다. 누르면 메뉴만 닫힙니다).
- "export"를 클릭하면 같은 자리에서 2단계로 바뀝니다: 3등분 원의 "pdf", "excel", "html".
- "excel": 저장 경로 창(위와 같은 표준 대화상자). "pdf"와 "html": 이벤트 기록에 남기고 닫습니다.
- 메뉴 밖을 클릭하거나 Esc를 누르면 닫힙니다.

화면 A, B, C의 데이터 패널과 화면 C의 셀 팝업에서 모두 동작합니다.

### 셀 팝업

화면 C에서 숫자 셀을 클릭하면 "불량 상세" 팝업 창이 뜹니다. 팝업에는 그 셀의 세부 표가 있고 엑셀 아이콘은 없습니다. 팝업의 표를 우클릭하면 원형 메뉴가 뜨고, 저장되는 것은 팝업의 표입니다.

### 저장되는 파일

실제 `.xlsx` 파일입니다. 첫 행은 열 이름, 그 아래는 화면에 보이는 행과 같은 내용입니다. 같은 화면과 같은 필터면 셀 내용이 같습니다. 이미 있는 파일을 고르면 표준 대화상자의 덮어쓰기 확인이 그대로 뜹니다.

## 노출 방식

컨트롤 묶음(영역)마다 접근성 트리에 보이는 방식을 고릅니다.

| 방식 | 트리에 보이는 모습 | 에이전트가 해야 하는 일 |
| --- | --- | --- |
| `ref` | 조작 가능한 역할과 이름이 있는 요소. ref가 붙음 | 지금처럼 ref로 조작 |
| `text` | 이름이 있는 텍스트 노드와 위치. ref 없음 | 글자를 찾아 그 좌표를 조작 |
| `pixel` | 영역 전체가 이름 없는 그림 하나. 안의 글자와 상태는 안 보임 | 스크린샷에서 읽거나 사람에게 물음 |

| 영역 | 포함하는 것 | 고를 수 있는 방식 | 기본 |
| --- | --- | --- | --- |
| `menu` | 메뉴바 카테고리, 목록 창의 항목 | `ref`, `text`, `pixel` | `ref` |
| `filters` | 필터 이름, 드롭다운 박스와 항목, 다중 선택 목록의 버튼·행 | `ref`, `text`, `pixel` | `text` |
| `grid` | 데이터 패널의 표와 화면 이름, 현재 화면 이름 탭, 상태 줄, 셀 팝업의 표 | `ref`, `text`, `pixel` | `text` |
| `icon` | 엑셀 아이콘 | `ref`(이름 있는 버튼), `pixel`(이름 없는 그림) | `pixel` |
| `radial` | 원형 메뉴 1·2단계 | `ref`, `text`, `pixel` | `pixel` |

기본값은 사용자가 회사에서 본 것(메뉴 항목에는 ref가 있고, ref는 많지 않으며, 대부분 글자이고, 원형 메뉴는 글자가 그려진 이미지)에 맞췄습니다. 기본 프로파일의 이름은 `mes-like`입니다.

고정으로 두는 것:

- "조회(F5)" 버튼, 날짜 입력 칸, "저장 | 열기 | 취소" 팝업의 버튼은 항상 `ref`입니다(설계자 판단: 표준 버튼과 입력란은 실제 앱에서도 대개 보입니다).
- 저장 경로 창은 Windows 표준 대화상자가 내보내는 그대로입니다.
- 로딩 팝업의 회전 이미지는 항상 그림이고, 안내 글은 텍스트 노드입니다.
- "조회된 데이터가 없습니다" 알림 창은 Windows 표준 메시지 상자 그대로입니다.

화면 이름 탭과 상태 줄은 `grid` 영역에 속합니다(설계자 판단). 화면 이름, 상태 줄, 표의 열 이름은 조작 대상이 아니므로 `ref` 방식에서도 `text`와 같게 보입니다. 표의 셀에는 `ref` 방식에서 ref가 붙습니다. 상태 줄은 조회가 끝나면 "조회 완료 · N건"만 보여 주고, 저장 결과나 저장 경로는 보여 주지 않습니다. 그래서 `hard`에서는 화면 진입과 조회 완료를 트리로 확인할 수 없고, 어느 프로파일에서도 저장 성공은 화면에 나오지 않습니다. 저장 성공은 하니스가 파일과 이벤트 기록으로 판정합니다.

`text` 방식에서 다중 선택 목록의 체크 표시는 그림으로만 그려지고 체크 표시와 상태는 트리에 나오지 않습니다. 행의 코드나 이름 글자를 눌러도 체크가 바뀝니다. 에이전트는 화면을 보고 확인해야 하며, 이 장면은 의도한 것입니다.

프로파일은 세 개입니다.

| 프로파일 | menu | filters | grid | icon | radial |
| --- | --- | --- | --- | --- | --- |
| `mes-like`(기본) | ref | text | text | pixel | pixel |
| `easy` | ref | ref | ref | ref | ref |
| `hard` | text | pixel | pixel | pixel | pixel |

`easy`는 지금 에이전트로 흐름 자체가 통하는지 볼 때, `hard`는 스크린샷 기반 관찰을 시험할 때 씁니다.

## 실행 옵션

```text
VirtualMes.exe [--profile mes-like|easy|hard]
               [--expose <영역>=<방식>[,<영역>=<방식>...]]
               [--delay-ms <N>] [--seed <N>]
               [--log <이벤트 기록 경로>]
               [--export-headless <화면> <필터 JSON> <출력 .xlsx>]
               [--parse-only]
```

- `--expose`는 프로파일 위에 영역별로 덮어씁니다. 영역이 지원하지 않는 방식을 주면 창을 띄우지 않고 종료 코드 2로 끝납니다.
- `--seed`의 기본값은 고정된 수입니다. 대기 시간 순서만 바꿉니다.
- `--export-headless`는 창을 띄우지 않고 주어진 화면과 필터의 결과를 `.xlsx`로 쓰고 끝납니다. 데스크톱을 건드리지 않는 테스트에 씁니다.
- `--parse-only`는 테스트용입니다. 옵션을 해석한 결과를 JSON 한 줄로 출력하고 창 없이 끝납니다.
- 잘못된 옵션은 표준 오류에 이유를 쓰고 종료 코드 2로 끝납니다. 창 없는 내보내기에서 파일을 쓰지 못하면 종료 코드 1입니다.

**옵션 파일:** 명령줄 인자가 하나도 없으면, 앱은 실행 파일 옆의 `VirtualMes.args` 파일을 읽어 그 안의 한 줄을 명령줄 인자로 씁니다(설계자 판단). 파일이 없으면 기본값으로 뜹니다. 지금 에이전트는 인자 없이 `agent-desktop launch <exe>`만 호출하고(`agent/tools.py`), `restart_target`도 인자 없이 다시 띄웁니다. 하니스가 실행 전에 이 파일을 써 두면 에이전트를 고치지 않고도 프로파일과 이벤트 기록이 재시작 뒤까지 유지됩니다. 이 파일은 Git에서 제외합니다.

## 이벤트 기록

`--log`를 주면 앱이 한 줄에 JSON 하나씩 덧붙입니다. 옵션이 없으면 쓰지 않습니다. 하니스만 읽고, 앱 창에는 이 기록의 내용이나 경로가 나오지 않습니다.

| 이벤트 | 담는 것 |
| --- | --- |
| `app_started` | 프로파일, 영역별 노출 방식, 시드 |
| `menu_opened` | 카테고리 |
| `screen_opened` | 화면 이름 |
| `filter_changed` | 화면, 필터, 새 값(다중 선택은 코드 목록), 닫힌 방법(`select_button`, `outside_click`, `item_click`, `deactivated`, `typed`) |
| `query_started` | 화면, 모든 필터 값, 시작 방법(`button`, `f5`), 대기 시간 |
| `query_finished` | 행 수 |
| `cell_popup_opened` | 행, 열 |
| `radial_opened` / `radial_closed` | 단계, 위치(패널 또는 셀 팝업), 닫힌 이유 |
| `export_choice` | 경로(`icon`, `radial`), 선택(`save`, `open`, `cancel`, `excel`, `pdf`, `html`, `copy`, `print`, `close`) |
| `export_saved` | 파일 경로, 출처(패널 또는 셀 팝업), 행 수, 저장한 표를 조회했을 때의 필터 값 |
| `query_rejected`, `export_rejected`, `export_failed` | 조회나 저장을 하지 못한 이유(틀린 날짜, 조회 전 저장, 쓸 수 없는 경로) |

모든 줄에 순번과 시각이 붙습니다. 각 줄은 쓰는 즉시 디스크에 내보내 앱이 강제 종료되어도 남습니다.

## 테스트

데스크톱을 건드리지 않는 테스트를 `examples/llm-agent/tests/`에 둡니다(`python -m pytest -q`로 함께 실행). 빌드된 `VirtualMes.exe`가 없으면 건너뜁니다.

- `--export-headless`로 만든 파일이 열 이름과 행을 가진 올바른 `.xlsx`다.
- 같은 화면과 필터로 두 번 만들면 셀 내용이 같다.
- 필터 값이 결과 행을 실제로 거른다(예: Shop을 하나만 고르면 그 Shop의 행만 나온다).
- 지원하지 않는 `--expose` 값과 잘못된 옵션은 종료 코드 2로 끝난다.

창을 띄우는 확인은 사용자가 PC를 쓰지 않을 때 따로 합니다(`CLAUDE.md`의 "실제 동작 확인"). 완료 기준은 다음과 같습니다.

1. `build.ps1`이 `VirtualMes.exe`를 만든다.
2. 세 프로파일 각각에서, 배경 문서의 흐름(메뉴 → 필터 → 조회 → 아이콘 저장, 우클릭 저장, 셀 팝업 저장)을 손으로 끝까지 할 수 있다.
3. `mes-like`에서 에이전트가 쓰는 것과 같은 옵션(`agent-desktop snapshot --window-id <창> --compact --include-bounds`, `-i` 없음. `-i`는 텍스트 노드를 빼므로 쓰지 않습니다)으로 창마다 스냅샷을 찍으면: 메뉴 항목에 ref가 있고, 필터 이름과 표의 글자는 ref 없이 위치가 있는 텍스트로 나오며, 열린 원형 메뉴의 창에는 "export"와 "excel"이 나오지 않는다.
4. `easy`에서는 조작 대상(필터 박스와 항목, 체크박스, 표의 셀, 엑셀 아이콘, 원형 메뉴의 칸)에 ref가 붙고, `hard`에서는 필터와 표의 글자가 트리에 나오지 않는다.
5. 손으로 한 흐름의 이벤트 기록에, 고른 필터 값과 저장한 파일 경로가 그대로 남는다.

## 빌더에게 맡기는 것

- 소스 파일 구성, 클래스 이름, 각 노출 방식을 WinForms에서 구현하는 방법. 기존 픽스처의 UIA 제공자 코드(`tests/fixture-app-windows/Fixture*Host.cs`)를 참고할 수 있지만 복사해서 의존하지는 않습니다.
- 고정 데이터 표의 내용(행 수, 값), Shop 1·2번 칸의 행, 원형 메뉴의 나머지 세 항목 이름, 빈 화면의 문구.
- `.xlsx`를 쓰는 방법. 외부 패키지 없이 .NET Framework에 들어 있는 것으로 씁니다.
- 이벤트 기록의 정확한 필드 이름. 위 표의 내용이 빠지지 않으면 됩니다.
- 색, 글꼴, 여백. 목업은 배치의 참고입니다.
- `examples/llm-agent/virtual-mes/README.md`: 빌드, 실행 옵션, 프로파일, 이벤트 기록 형식.

## 미확인

- 실제 MES에서 Shop 1·2번 칸이 3번 칸과 같은 다중 선택인지.
- 실제 MES가 화면을 여러 탭으로 여는지.
- 실제 MES의 저장 경로 창이 Windows 표준 대화상자인지.
- 원형 메뉴의 "export" 외 항목 이름.
- 실제 MES에서 드롭다운 목록과 원형 메뉴가 별개의 창으로 뜨는지, 본 창 안에 그려지는지.
- 실제 MES에서 목록 밖을 클릭해 닫을 때 그 클릭이 아래 컨트롤에도 전달되는지.

확인되면 이 문서와 앱을 고칩니다. 어느 것도 공통 기능 개발을 막지 않습니다.
