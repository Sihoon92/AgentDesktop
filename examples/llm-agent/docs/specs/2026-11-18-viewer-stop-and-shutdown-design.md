# 뷰어에서 실행 멈추기와 안전하게 종료하기 설계

- 날짜: 2026-11-18
- 상태: 사용자 승인(2026-11-18, "권장대로 해줘"), 구현됨(커밋 전). 구현 계획: [2026-11-18-viewer-stop-and-shutdown](../plans/2026-11-18-viewer-stop-and-shutdown.md)
- 대상: `examples/llm-agent`의 실행 멈추기(`agent/loop.py`, `agent/ask.py`, `agent/approval.py`, `agent/ready.py`, `agent/tools.py`, `viewer/run_manager.py`), 뷰어 서버와 프로세스(`viewer/server.py`, `view.py`, 새 `viewer/instance.py`), 화면(`viewer/static/`). `agent-desktop` CLI는 고치지 않습니다.

## 왜 하는가

사용자는 뷰어로 실행하다가 중간에 멈추고 싶을 때 터미널에서 Ctrl+C로 끝냅니다. 그 뒤 뷰어를 다시 열면 동작하지 않습니다.

원인은 이 PC에서 확인했습니다.

- 뷰어 서버(`ThreadingHTTPServer`)는 `SO_REUSEADDR`를 켭니다. Windows에서 이 옵션은 다른 프로세스가 이미 듣고 있는 포트에도 겹쳐 열기를 허용합니다. 같은 포트에 서버 두 개가 오류 없이 뜨는 것을 확인했습니다.
- Ctrl+C가 파이썬에 전달되지 않는 터미널에서 실행했거나 창을 그냥 닫았으면 옛 뷰어가 남습니다. 그 상태로 새 뷰어를 열면 같은 포트에 둘이 뜹니다. 브라우저 요청이 옛 프로세스로 가면 옛 프로세스는 새 토큰을 모르니 거절하고, 화면이 동작하지 않습니다.
- 실행 도중에 끊으면 실행 기록이 "실행 중"으로 남았다가 나중에 "끊김"으로 보입니다. 요약도 남지 않습니다.

## 목표와 하지 않는 것

목표:

1. 뷰어에 **실행 멈춤** 버튼이 있습니다. 뷰어는 켠 채 지금 실행만 멈추고, 기록은 `stopped`와 "사용자가 실행을 멈췄습니다"로 끝나며 요약도 남습니다.
2. 뷰어에 **뷰어 종료** 버튼이 있습니다. 실행 중이면 화면 안에서 확인을 받고, 실행을 멈춘 뒤 서버를 닫습니다.
3. Ctrl+C도 종료 버튼과 같은 길로 정리합니다. 한 번 더 누르면 기다리지 않고 바로 끕니다.
4. 뷰어를 다시 열 때 포트 때문에 실패하거나 옛 뷰어와 겹치지 않습니다.
5. 어디선가 남아 있는 뷰어를 `python view.py --stop`으로 끌 수 있습니다.

하지 않는 것:

- 대상 앱(MES)을 닫는 것. 멈추거나 종료해도 대상 앱은 그대로 둡니다(사용자 결정). 사람이 화면을 이어서 볼 수 있고, 닫다가 저장하지 않은 내용을 잃을 위험이 없습니다. 다음 실행 전에는 사람이 닫습니다("이미 떠 있으면 멈춤" 규칙).
- 진행 중인 모델 호출이나 CLI 명령을 중간에 끊는 것. 끊으면 앱에 반쯤 전달된 동작이 생길 수 있으므로, 그것이 끝난 직후에 멈춥니다.
- 터미널 창을 X로 닫는 경우를 잡는 것. Windows에서 파이썬이 그 신호를 믿을 만하게 받지 못합니다. 남은 뷰어는 다음 실행이 알아보고 정리합니다(4절).
- `run.py --view`의 뷰어. 그 뷰어는 실행 하나를 따라가는 보기 전용이고 Enter로 닫습니다. 바꾸지 않습니다.

## 1. 실행 멈추기

`RunManager.stop(run_id)`가 멈춤 요청을 받습니다.

- 실행마다 멈춤 신호(`threading.Event`) 하나를 둡니다. 루프, 준비 기다리기, 질문·승인 대기가 이 신호를 봅니다.
- **루프:** 모델을 부르기 전과 도구를 하나 실행하기 전마다 신호를 봅니다. 신호가 있으면 `AgentStopped("사용자가 실행을 멈췄습니다")`로 끝납니다. 지금의 멈춤 경로(단계 멈춤 이벤트, 기록 마무리, 요약)를 그대로 지납니다.
- **질문·승인 대기:** 멈추면 기다리던 질문과 승인이 바로 "답 없음"으로 풀리고, 그 뒤의 질문도 기다리지 않습니다. 루프는 풀린 이유가 멈춤인지 먼저 보고 "사용자가 실행을 멈췄습니다"로 끝냅니다. "답이 없어 멈춤"으로 끝나지 않습니다.
- **준비 기다리기:** 다시 읽기 사이에 신호를 봅니다. 신호가 있으면 새 상태 `cancelled`로 끝나고, 모델을 부르지 않습니다.
- **진행 중인 모델 호출이나 CLI 명령:** 끝날 때까지 기다린 뒤 멈춥니다. 뷰어는 그동안 "멈추는 중"을 보여 줍니다.

## 2. 뷰어 종료

- 서버에 종료 요청이 오면, 진행 중인 실행이 없을 때는 바로 서버를 닫습니다.
- 실행 중이면 요청이 "실행도 멈춤"을 담고 있을 때만 진행합니다. 담고 있지 않으면 실행 중이라고 거절하고, 화면이 그 거절을 받아 확인을 묻습니다.
- 실행을 멈추면 실행 스레드가 기록과 요약을 마칠 때까지 최대 120초 기다립니다. 모델 호출이 그보다 오래 걸리면 기다리지 않고 닫고, 그 기록은 나중에 "끊김"으로 보입니다.
- 서버는 응답을 보낸 뒤 닫힙니다. 화면에는 "뷰어를 종료했습니다. 다시 열려면 터미널에서 python view.py"가 남습니다.
- 종료 버튼은 `view.py`로 띄운 뷰어에만 있습니다.

## 3. Ctrl+C

- `view.py`가 Ctrl+C(그리고 Windows의 Ctrl+Break)를 받으면 2절과 같이 정리합니다. "실행을 멈추는 중입니다. 바로 끄려면 Ctrl+C를 한 번 더 누르세요"를 출력합니다.
- 두 번째 Ctrl+C는 기다리지 않고 끝냅니다.

## 4. 다시 열기

- **포트 독점:** Windows에서는 `SO_REUSEADDR`를 끄고 `SO_EXCLUSIVEADDRUSE`로 엽니다. 이미 쓰이는 포트면 열기가 실패하므로 겹쳐 뜨지 않습니다.
- **뷰어 표시 파일:** `view.py`의 뷰어는 시작할 때 기록 폴더에 `.viewer.json`(pid, 그 프로세스의 시작 시각, 포트, 토큰)을 쓰고, 정상 종료할 때 지웁니다. 기록 폴더는 Git에서 제외되고, 토큰은 이 PC의 같은 사용자만 읽습니다.
- **포트가 쓰이고 있을 때:**
  1. 표시 파일의 프로세스가 살아 있고(pid와 시작 시각이 같음) 그 포트가 맞으면 옛 뷰어입니다. 진행 중인 실행이 없으면 그 뷰어에 종료를 요청하고, 최대 10초 기다린 뒤 그 포트로 엽니다.
  2. 옛 뷰어가 실행 중이면 끄지 않습니다. 다음 빈 포트로 열고 "다른 뷰어에서 실행 중입니다(포트 N)"를 알립니다.
  3. 옛 뷰어가 아니면(다른 프로그램, 죽은 프로세스의 남은 파일) 다음 빈 포트로 열고 알립니다. 남은 표시 파일은 덮어씁니다.
  - 빈 포트는 요청한 포트부터 20개까지 찾습니다. 모두 쓰이면 지금처럼 오류로 끝납니다.
- **`python view.py --stop`:** 표시 파일의 뷰어에 "실행도 멈추고 종료"를 요청하고 결과를 출력합니다. 표시 파일이 없거나 프로세스가 없으면 그렇게 알리고 파일을 지웁니다.

## 5. 화면

- 위쪽 줄 오른쪽에 **실행 멈춤**과 **뷰어 종료** 버튼을 둡니다. 실행 멈춤은 진행 중인 실행이 있을 때만 켜집니다.
- 확인은 브라우저의 `confirm` 창이 아니라 화면 안의 작은 띠로 받습니다(브라우저 대화상자는 자동화 도구를 막음).
  - 실행 멈춤: "실행을 멈출까요? 대상 앱은 그대로 둡니다. [멈춤] [취소]"
  - 실행 중 종료: "실행 중인 작업을 멈추고 뷰어를 종료할까요? [멈추고 종료] [취소]"
- 멈춤을 요청한 뒤 실행이 끝날 때까지 "멈추는 중…"을 보여 줍니다.
- 종료 뒤에는 화면 전체를 덮는 안내를 띄우고 더 이상 서버에 묻지 않습니다.

## 6. 기록과 요약

- 멈춘 실행은 `status: stopped`, `reason: 사용자가 실행을 멈췄습니다`입니다. 요약의 판정 줄은 지금처럼 상태 코드만 보여 줍니다.
- 준비 기다리기 중에 멈추면 `run.json`의 `ready.status`가 `cancelled`입니다.
- 이벤트에 `{"type": "stop_requested"}`를 남겨, 사람이 멈춘 시점을 뷰어 타임라인 뒤에서 알 수 있게 합니다.

## 방법 비교

1. **멈춤 신호를 하니스 곳곳에서 보기(고름).** 끊어도 안전한 자리(모델 호출 전, 도구 실행 전, 대기 중)에서만 멈추므로 앱 상태와 기록이 어긋나지 않습니다.
2. **실행 스레드를 강제로 끝내기.** 파이썬은 스레드를 밖에서 안전하게 죽일 수 없고, 반쯤 전달된 동작과 마무리되지 않은 기록이 남습니다.
3. **포트만 매번 새로 고르기(`--port 0`).** 다시 열기 문제는 피하지만, 옛 뷰어가 계속 떠 있고 실행 중인 작업을 멈출 길은 생기지 않습니다.

## 설계자가 정한 것 (사용자가 말한 것이 아님)

1. 종료할 때 실행을 마무리하기를 기다리는 최대 시간은 120초, 옛 뷰어가 꺼지기를 기다리는 시간은 10초입니다.
2. 빈 포트는 요청한 포트부터 20개까지 찾습니다.
3. 표시 파일은 기록 폴더의 `.viewer.json`입니다. 실행 목록은 실행 id 모양의 폴더만 읽으므로 섞이지 않습니다.
4. 실행 중인 옛 뷰어는 새 뷰어가 끄지 않습니다. 실행을 잃지 않게 하려는 것입니다. 끄려면 `--stop`이나 그 뷰어의 종료 버튼을 씁니다.
5. 터미널 창 닫기는 잡지 않습니다(위 "하지 않는 것").
