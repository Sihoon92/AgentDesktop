# workflow 만들기와 파라미터 재실행 구현 계획

> **에이전트 작업자에게:** 작업마다 superpowers:test-driven-development를 따릅니다. 단계는 체크박스(`- [ ]`)로 표시합니다.

- 날짜: 2026-11-19
- 상태: 사용자 승인(2026-11-19), 작업 1~10 수락, 통합 확인 끝(실제 창 확인 전)
- 설계: [workflow 만들기와 파라미터 재실행 설계](../specs/2026-11-19-workflow-design.md) (사용자 승인 2026-11-19). 값과 규칙은 설계가 기준이고, 이 계획은 파일, 이름, 시그니처, 테스트, 순서를 정합니다. 구현하는 사람은 둘 다 읽습니다.

**목표:** 성공한 모델 실행이 끝나면 기록에서 workflow를 만들어 저장하고, 그 workflow를 ID와 파라미터 값으로 모델 없이 다시 실행합니다.

**구조:** 만들기는 기록 폴더만 읽습니다: `agent/run_record.py`가 기록을 읽고, `agent/workflow_author.py`가 모델의 초안(기록의 번호만 가리킴)에 `agent/locator.py`의 대상 적기를 채워 `agent/workflow_format.py`의 형식으로 만들고, `agent/workflow_store.py`가 저장합니다. 재실행은 `agent/workflow_run.py`가 지금의 `Toolbox`와 `RunRecorder`로 단계를 실행합니다. 입구는 `run.py`와 뷰어입니다.

**쓰는 것:** Python 표준 라이브러리와 지금의 의존성(PyYAML, Pillow). 더하는 의존성은 없습니다.

## 전체에 걸친 조건

- 재실행은 모델을 부르지 않습니다. `agent/workflow_run.py`는 `agent.llm`을 import하지 않습니다.
- workflow 파일과 대상 적기에 좌표, 표시 번호, ref, 창 id를 넣지 않습니다.
- 후보가 0개나 2개 이상이면 추측하지 않고 멈춥니다. 확인 조건이 깨져도 모델이 이어받지 않습니다.
- `agent/`와 `viewer/` 코드에 앱 이름이나 화면의 글을 넣지 않습니다(`tests\test_application_agnostic.py`). 새 모듈도 이 검사를 받습니다. 테스트와 문서의 예시에는 넣어도 됩니다.
- 코드(7절)에는 화면의 글이 없습니다. `run.json`, 요약, 실행 끝의 한 줄에는 수, 코드, workflow ID만 넣습니다. 단계의 목표, 파라미터의 이름과 값, 저장 경로는 `events.jsonl`과 workflow 파일에만 둡니다.
- 제한 시간: 단계 15초, 저절로 닫히는 창 180초, 다시 읽는 간격 0.5초.
- 모델 실행의 동작은 아래 둘 말고는 바뀌지 않습니다: `plan`에 `params`가 생기고, 요소 기록에 `mark`와 `scope`가 생깁니다. 지금의 테스트는 이 둘 때문에 고치는 것 말고는 그대로 통과해야 합니다. 다른 이유로 고쳐야 하면 오케스트레이터에게 먼저 묻습니다.
- 작업자는 커밋하지 않고, 실제 창을 띄우는 실행과 실제 모델 호출을 하지 않습니다(`VIRTUAL_MES_LIVE=1` 테스트 포함). 데스크톱은 `tests/fake_cli.py`의 장면(scene)으로, 모델은 가짜로 시험합니다.
- 테스트는 `examples/llm-agent`에서 `/c/Users/sihoo/anaconda3/envs/AgentDesktop/python.exe -m pytest -q`(아래 `pytest`)로 돌립니다. 제출 전 전체 실패 0. 테스트마다 구현을 되돌려 실패하는지 확인하고 보고서에 적습니다.

## 검토에서 특히 볼 것

설계가 말하지 않았지만 쓰는 사람이 곧 만날 입력입니다. 각 항목의 테스트는 괄호 안의 작업에 있습니다.

1. **`--param shop=WA0, WA1,,WA0`처럼 빈칸, 빈 조각, 중복이 섞인 값.** 앞뒤 공백을 지우고 중복을 한 번만 남깁니다. 빈 조각이 있거나 남는 값이 없으면 시작 전에 `PARAM_INVALID`입니다. (작업 4)
2. **상대 경로이거나 폴더가 없는 저장 경로.** 앱을 대화상자까지 몰고 간 뒤가 아니라 시작 전에 `PARAM_INVALID`로 거절합니다. (작업 4)
3. **손으로 고치다 깨졌거나 쓰다 만 workflow 파일.** 목록은 그 파일을 건너뛰고 나머지를 보여 주며, 그 ID의 재실행은 `WORKFLOW_INVALID`입니다. 뷰어의 목록이 죽지 않습니다. (작업 4, 작업 9)
4. **재실행 도중 대상 앱이 꺼짐.** 창이 하나도 없으면 15초를 기다리지 않고 `APP_GONE`으로 멈춥니다. (작업 7)
5. **목록의 전부를 고르는 값, 그리고 대소문자만 다른 값.** 전부면 "전체 선택"만 누르고 통과합니다. 이름은 앞뒤 공백만 무시하고 똑같아야 하며, 대소문자가 다르면 `PARAM_VALUE_NOT_FOUND`입니다. (작업 7)

## 계약

**C1. 요소의 `mark`와 `scope` (작업 1):** `observe.render_marked`의 표시 번호 맵과 `observe.visible_elements`의 요소마다 두 키가 더 있습니다. `"mark": int`는 그 관찰의 표시 번호이고, `"scope": int | None`은 트리에서 가장 가까운 조상 가운데 역할이 `window`인 요소의 표시 번호입니다. 관찰한 창(뿌리)은 조상으로 치지 않으므로 그 바로 아래는 `None`입니다. 기록의 관찰 이벤트 `elements`에도 그대로 들어갑니다.

**C2. `plan`의 `params` (작업 1):** 도구 스키마에 `params: [{"name": str, "value": str}]`(필수, 빈 배열 가능). `StagePlan.set(stages, params=None)`이 검사합니다: 이름은 `^[a-z][a-z0-9_]{0,31}$`, 서로 다름, 12개 이하, `value`는 비어 있지 않은 글. 어긋나면 `StageError("bad_params", ...)`. `plan` 이벤트에 `"params": [...]`가 들어갑니다(없으면 `[]`).

**C3. 저장 경로 이벤트 (작업 1):** 성공 판정이 끝날 때 `{"type": "finish_note", "by": "human"|"harness", "saved_path": str|None}`를 로그로 보냅니다. 기록기는 이것과 `workflow`, `workflow_step`을 `KEPT_EVENTS`에 넣습니다.

**C4. `agent/run_record.py` (작업 2)**

```python
class RecordError(Exception):          # .code: "RUN_NOT_FOUND" | "RUN_NOT_SUCCESSFUL" | "NO_PLAN" | "RECORD_TOO_OLD"
@dataclass(frozen=True)
class RunRecord:
    run_id: str
    goal: str
    system: str | None
    permission_level: int
    params: list[dict]             # 마지막 plan 이벤트의 params
    stages: list[dict]             # 마지막 plan의 stages에 stage 이벤트의 note를 붙인 것
    actions: list[dict]            # 아래
    observations: dict[int, dict]  # 관찰 id → 관찰 이벤트 그대로
    saved_path: str | None         # finish_note의 saved_path
    main_window: str | None        # 첫 관찰의 window.id
def read_record(run_dir, status=None) -> RunRecord   # status를 주면 run.json의 값 대신 그것으로 성공 여부를 봄
```

`status`는 실행이 끝나기 직전(기록기가 아직 `running`이라고 적어 둔 때)에 만들기를 부르는 쪽을 위한 것입니다.

`actions`의 항목: `{"n": int(1부터), "step", "tool", "intent", "arguments", "target", "result", "before": 관찰 id|None, "after": 관찰 id|None, "delivered": bool}`. `after`는 그 동작 이벤트 뒤 다음 동작 이벤트 전에 처음 나오는 `source == "action"`인 관찰입니다. `delivered`는 `result`에 `refused`가 없고, `ok`가 `False`가 아니고, `disposition.delivery`가 `not_delivered`가 아닐 때 참입니다. `run.json`의 `status`가 `verified`나 `confirmed`가 아니면 `RUN_NOT_SUCCESSFUL`, plan 이벤트가 없으면 `NO_PLAN`, 관찰의 요소에 `mark`가 없으면 `RECORD_TOO_OLD`입니다.

**C5. `agent/locator.py` (작업 3):** 요소 목록(C1의 dict들)만 받는 순수 함수입니다.

```python
class LocatorError(ValueError): ...
def in_scope(elements, scope_mark) -> list[dict]     # scope == scope_mark인 요소. 창 요소 자신은 뺌
def window_elements(elements) -> list[dict]          # role == "window"인 요소
def new_windows(before, after) -> list[dict]         # after의 창 요소 가운데 before에 없던 것
def window_handle(elements, window) -> dict          # {"name": str|None, "nth": int}: 이름이 같은 창 요소 중 몇 번째(1부터)
def resolve_handle(elements, handle) -> dict | None  # 그 창 요소, 없으면 None
def describe(scoped, mark, avoid=()) -> dict         # 대상 적기에서 scope를 뺀 것. 하나로 못 좁히면 LocatorError.
                                                     # avoid의 이름은 기준으로 쓰지 않음(실행 중 바뀐 값)
def find(scoped, locator, name=None) -> list[dict]   # 맞는 요소 전부. name이 있으면 locator의 name 대신 씀
```

`describe`가 내는 dict의 키: `role`(항상), `name`·`description`(있을 때만), `near: {"name", "relation": "same_row"|"same_column", "nth": int}`(역할·이름·설명만으로 하나가 안 될 때만). `find(scoped, describe(scoped, m))`은 항상 표시 번호 `m`인 요소 하나만 돌려줍니다. `new_windows`는 창 요소를 `(이름, 같은 이름 가운데 순서)`로 견줍니다.

**C6. `agent/workflow_format.py` (작업 4)**

```python
FORMAT = 1
STEP_KINDS = ("act", "select_only", "check_file")
ACT_TOOLS = ("click", "toggle", "expand", "collapse", "set_value", "select", "check", "uncheck",
             "type", "double_click", "right_click", "click_part", "press")
VALUE_TOOLS = {"set_value": "value", "select": "value", "type": "text"}   # 값 인자의 이름
EXPECTS = ("window_opened", "window_closed", "content_changed", "value_changed", "any", "picture_changed")
PARAM_KINDS = ("text", "list", "path")
class WorkflowError(ValueError):       # .code
def check_workflow(workflow: dict) -> dict            # 그대로 돌려주거나 WorkflowError("WORKFLOW_INVALID")
def param_name(value) -> str | None                   # "$shop" → "shop", 그 밖은 None
def resolve_values(workflow, given: dict[str, str], run_id: str) -> dict[str, str | list[str]]
def other_values(workflow, values) -> bool            # path가 아닌 파라미터 가운데 예시와 다른 것이 있음
```

파일의 꼴(설계 6절의 예시와 같고, 아래가 정확한 키입니다):

- 맨 위: `format`, `id`, `system`, `goal`, `source: {run_id, date}`, `status`(`unverified`|`verified`), `passes`, `failures`, `verified_with_other_values`, `permission_level`, `params: {이름: {kind, example}}`, `fixed: [{name, value}]`, `steps`.
- 범위(`scope`): `"main"` | `{"opened_by": N}`(N번 단계가 연, 트리 안의 창 요소) | `{"opened_by": N, "top": true}`(N번 단계가 연, 따로 읽는 창). N은 앞선 단계의 번호여야 합니다.
- `act` 단계: `n`, `goal`, `do`, `tool`, `args`(`click_part`는 `{part, action}`, `press`는 `{combo}`, 그 밖은 `{}`), `target: {scope, role, name?, description?, near?}`(`press`는 `{scope}`만), `value`(`VALUE_TOOLS`의 도구만, 글이나 `$이름`), `expect`(`EXPECTS` 중 하나나 null), `closes: N`(`window_closed`일 때만), `settle: true`(있을 때만).
- `select_only` 단계: `n`, `goal`, `do`, `scope`(`main`이 아님), `all: {role, name?, description?, near?}`, `item_role`, `items: $이름`.
- `check_file` 단계: `n`, `goal`, `do`, `path: $이름`.
- `target.name`과 `value`는 `$이름`일 수 있습니다. 쓰인 `$이름`은 모두 `params`에 있어야 하고, `params`의 이름은 모두 한 번 이상 쓰여야 합니다. `list`는 `select_only.items`에만, `path`는 `value`와 `check_file.path`에만 씁니다.
- 모르는 키, 숫자 좌표 키(`x`, `y`, `bounds`, `rect`, `points`), `mark`, `ref`, `window_id`가 어디든 있으면 `WORKFLOW_INVALID`입니다.

`resolve_values`: 모르는 이름과 `fixed`의 이름은 `PARAM_UNKNOWN`. 주지 않은 이름은 예시 값. `text`는 앞뒤 공백을 지우고 비면 `PARAM_INVALID`. `list`는 쉼표로 나누고 "검토에서 특히 볼 것" 1을 따릅니다. `path`는 절대 경로이고 폴더가 있어야 하며(`PARAM_INVALID`), 이미 있으면 `FILE_EXISTS`입니다. 주지 않은 `path`는 예시의 폴더에 `<이름>-<run_id><확장자>`입니다.

**C8. `agent/workflow_author.py` (작업 5)**

```python
class AuthorError(Exception):          # .code: "MODEL_NO_DRAFT" | "DRAFT_INVALID" | "LOCATOR_NOT_UNIQUE" | "PICTURE_TARGET"
PROPOSE_WORKFLOW: dict                 # strict 함수 도구 "propose_workflow"
def draft(model, record) -> tuple[dict | None, int]     # (초안, 쓴 토큰). 도구 호출이 없으면 None
def build(record, draft) -> dict                        # id·status·횟수가 없는 workflow. AuthorError
def make_workflow(model, run_dir, store, log, today=None, status=None) -> tuple[dict, int]
def after_run(model, result, run_dir, store, log) -> RunResult
```

초안의 꼴: `{"params": [{"name", "kind"}], "steps": [{"kind", "goal", "action": int|null, "actions": [int]|null, "observation": int|null, "all_mark": int|null, "item_marks": [int]|null, "param": str|null}]}`. `act`는 `action`과 `param`을, `select_only`는 `actions`, `observation`, `all_mark`, `item_marks`, `param`을, `check_file`은 `param`을 씁니다.

`make_workflow`는 예외를 내지 않습니다. `{"created": bool, "id": str|None, "code": str|None, "steps": int, "params": int}`를 돌려주고 같은 내용을 `{"type": "workflow", ...}` 이벤트로 `log`에 보냅니다. `after_run`은 `result.status`가 성공일 때만 `make_workflow`를 부르고 토큰을 더한 `result`를 돌려줍니다. `after_run`은 `recorder.finish` 앞에서 불리므로 그때 `run.json`은 아직 `running`입니다. 그래서 `result.status`를 `status`로 넘깁니다.

**C9. `Toolbox` (작업 6):** 생성자에 `gated: bool = True`. `False`면 질문 정책이 동작을 막지 않고(`_gate`가 항상 통과), 정책에 결과를 알리지도 않으며, 반복 동작 가드(`ActionGuard`)도 돌지 않습니다. 가드는 같은 서명의 동작을 실행 전체에서 3번까지만 허용하는데, 재실행은 목록마다 같은 이름의 요소("전체 선택", 닫기)를 누르므로 목록이 넷이면 멈춥니다. 권한 단계와 대상 프로세스 고정은 그대로입니다. `marked_elements() -> list[dict]`는 가장 최근 관찰의 요소를 표시 번호 순으로 복사해 돌려줍니다(C1의 키 포함). `current_window -> str | None` 속성.

**C10. `agent/workflow_run.py` (작업 7)**

```python
STEP_TIMEOUT_S = 15
SETTLE_TIMEOUT_S = 180
POLL_S = 0.5
def run_workflow(toolbox, task, workflow, values, log=lambda _e: None, stop=None, started_at=None) -> RunResult
def record_outcome(store, workflow, values, result) -> None    # 통과면 note_pass(other_values), 멈춤이면 note_failure
```

통과는 `RunResult("verified", 단계 수, "workflow 통과", stats=...)`, 멈춤은 `RunResult("stopped", 끝낸 단계 수, 코드, stats=...)`입니다. `stats`는 `{"workflow_run": {"id", "steps", "steps_done", "code"}}`(통과면 `code`는 `None`). 단계마다 `{"type": "workflow_step", "n", "kind", "ok": bool, "code": str|None, "ms": int, "goal": str}`를 `log`에 보냅니다. 시간은 `toolbox.clock`과 `toolbox.sleep`만 씁니다.

**C11. `run.json`과 요약 (작업 10):** `workflow` 이벤트가 오면 `run.json`에 `"workflow": {"created", "id", "code"}`. `finish`의 `stats`에 `workflow_run`이 있으면 `run.json`에 그대로. 요약에 `  workflow: 만듦 w-… · 단계 12 · 파라미터 2` 또는 `  workflow: 못 만듦 · LOCATOR_NOT_UNIQUE`, 재실행에는 `  재실행: w-… · 단계 5/12 · EXPECT_UNMET`(통과면 코드 자리에 `통과`).

**C12. `run.py` (작업 8):** 인자 `--workflow <ID>`, `--param 이름=값`(여러 번), `--workflows`, `--make-workflow <run_id|latest>`, `--workflow-dir <폴더>`. 설정 키 `workflow_dir`. 재실행의 `started_by`는 `"workflow"`, `model`은 `"workflow"`.

**C13. `RunManager` (작업 9):** `workflows(system=None) -> list[dict]`(항목: `id`, `goal`, `status`, `passes`, `failures`, `verified_with_other_values`, `params: [{name, kind, example}]`, `fixed`), `start_workflow(workflow_id, values: dict[str, str], system=None) -> run_id`. 모르는 ID, 틀린 값은 `InvalidRun`(글에 코드 포함)입니다.
