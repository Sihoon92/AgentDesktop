# 가상 MES의 선택 칸을 화살표로만 열리게 하는 수정 계획

- 날짜: 2026-11-14
- 상태: 사용자 승인(2026-11-14). 구현했고 창 없는 테스트가 통과합니다. `build\VirtualMes.exe`의 교체와 실제 창 확인은 아직 하지 않았습니다.
- 대상: `examples/llm-agent/virtual-mes/`와 그 테스트. 에이전트 코드(`agent/`, `viewer/`)는 고치지 않습니다.

## 왜 고치는가

실제 MES에서는 Shop, 기간 같은 조건 칸의 오른쪽 화살표 버튼을 정확히 눌러야 목록이 열립니다. 칸의 왼쪽은 글을 쓸 수 있는 칸처럼 생긴 곳도 있고, 거기를 누르면 목록이 열리지 않습니다(사용자 설명, 2026-11-14).

가상 앱에는 이 동작이 이미 있지만 옵션(`--combo-open arrow`)을 줘야만 켜집니다. 실제 MES와 다른 점은 세 가지입니다.

| | 지금의 가상 앱 | 실제 MES(사용자 설명) |
| --- | --- | --- |
| 기본 동작 | 칸 어디를 눌러도 열림. `--combo-open arrow`를 줘야 화살표로만 열림 | 언제나 화살표로만 열림 |
| 모양 | 칸 하나에 화살표 그림이 붙어 있음. 두 방식의 모양이 같음 | 화살표가 칸과 구분된 버튼. 왼쪽은 입력 칸처럼 보이는 곳도 있음 |
| 접근성 정보 | 기본 프로파일(`mes-like`)에서는 화살표가 요소로 나오지 않음. `easy`에서만 이름 `열기`인 버튼 | 화살표와 칸이 서로 다른 정보를 가진 요소로 보임(사용자 추정, 미확인) |

기본 동작이 달라서, 옵션을 주지 않고 실행한 장면에서는 에이전트가 칸 가운데를 눌러도 열립니다. 실제 MES에서 생기는 실패가 가상 앱에서 재현되지 않습니다.

## 고칠 것

### 1. 기본값을 화살표로

- `--combo-open`의 기본값을 `arrow`로 바꿉니다. 옵션 없이 실행하면 모든 필터 칸(Shop 세 칸, 공정, 제품, 설비, 기간)이 화살표로만 열립니다.
- `--combo-open anywhere`는 남깁니다. 옛 동작과 비교할 때만 씁니다.
- 비활성 칸은 지금처럼 몸통도 화살표도 반응하지 않습니다.

### 2. 모양을 실제에 가깝게

- 화살표를 칸 오른쪽 끝의 구분된 버튼으로 그립니다(테두리와 버튼 바탕색, 눌렀을 때의 눌림 표시).
- 몸통은 입력 칸처럼 그립니다(흰 바탕). 몸통을 누르면 지금처럼 글자 뒤에 입력 커서가 깜빡이고 목록은 열리지 않습니다.
- `anywhere`일 때의 모양은 지금과 같게 둡니다.

### 3. 화살표의 접근성 정보를 따로 정할 수 있게

지금은 화살표의 노출이 `filters` 영역을 따라가서, 칸의 글자는 글자로만 보이면서 화살표는 요소로 보이는 조합을 만들 수 없습니다. 실제 MES가 어느 쪽인지 모르므로 따로 고를 수 있게 합니다.

- `--expose`에 영역 `arrow`를 더합니다. 방식은 세 가지입니다.

| 방식 | 접근성 트리에 보이는 것 |
| --- | --- |
| `ref` | 이름 `열기`인 `button`. `AutomationId`는 `<칸 id>-arrow` (지금 `easy`의 모양) |
| `bare` | 이름 없는 `button`. `AutomationId`는 칸마다 고정된 숫자. 캡처의 번호나 id로만 구분됨 |
| `pixel` | 요소 없음. 칸의 오른쪽 끝 위치를 눌러야 함 (지금 `mes-like`의 모양) |

- 프로파일의 기본: `easy`는 `ref`, `mes-like`는 `bare`, `hard`는 `pixel`.
- `mes-like`를 `bare`로 두는 것은 가정입니다. G-SCM의 그림 메뉴에 숫자 `AutomationId`가 있었다는 관찰과, 화살표와 칸이 서로 다른 정보를 가진다는 설명에 맞춘 것입니다. 실제 MES에서 화살표가 어떻게 보이는지 확인되면 기본값을 그에 맞춥니다.
- 이벤트 기록(`combo_body_clicked`, `combo_arrow_clicked`)과 `app_started`의 `combo_open`은 그대로이고, `app_started`의 `expose`에 `arrow`가 더해집니다.

## 같이 바뀌는 것

- **테스트:** `tests/test_virtual_mes.py`의 기본값 테스트, `tests/test_virtual_mes_live.py`에서 옵션 없이 칸을 눌러 목록을 여는 테스트(화살표를 누르도록 바꾸거나 `--combo-open anywhere`를 명시), `tests/virtual_mes_support.py`의 목록 여는 도우미, `tests/test_scenes_live.py`의 3·4·5번 장면(옵션 없이 실행), `tests/fixtures/snapshot_virtual_mes_*.json`(손으로 만든 세 프로파일 응답에 화살표 반영).
- **문서:** `virtual-mes/README.md`의 옵션 표와 "선택 칸 여는 방식", `docs/checklists/2026-11-13-observe-ask-learn.md`의 옵션 세트(화살표가 기본이 되어 세트가 둘로 줄어듦), `knowledge.example`의 설명은 그대로 맞음.
- **에이전트:** 코드 변경 없음. 다만 `mes-like`에서 화살표가 이름 없는 버튼으로 보이게 되므로, 실제 모델이 그 버튼을 번호로 골라 누르는지를 점검표의 2번 장면으로 다시 봅니다.

## 하지 않는 것

- 실제 MES의 다른 컨트롤(날짜 입력, 표, 원형 메뉴)의 동작 변경.
- 칸마다 몸통의 반응을 다르게 하기(어떤 칸은 커서, 어떤 칸은 무반응). 필요하면 실제 MES의 칸별 동작을 확인한 뒤 따로 합니다.
- `agent-desktop` CLI(Rust) 변경.

끝났다고 보는 기준:

- 옵션 없이 실행한 가상 앱에서 칸의 몸통을 누르면 목록이 열리지 않고, 화살표를 누르면 열립니다(이벤트 기록으로 확인).
- `--combo-open anywhere`에서는 화면과 접근성 트리가 이번 변경 전과 같습니다.
- 세 프로파일에서 화살표가 위 표대로 보입니다(`check.py`의 앱 관찰에서 `mes-like`의 "이름 없는 ref"가 늘어남).
- 창 없는 테스트와 실제 창 테스트가 통과합니다.

## 확인이 필요한 것

- 실제 MES에서 화살표가 접근성 정보로 어떻게 보이는지(이름이 있는지, `AutomationId`가 있는지, 아예 요소가 아닌지). 회사에서 조건 칸이 보이는 화면을 연 채 `python check.py`를 돌린 결과(이름 없는 ref의 수, id 있음의 수)로 가늠할 수 있습니다.
- (확인됨, 2026-11-14) 활성 필터 칸의 몸통을 누르면 커서가 뜨고, 비활성 칸은 커서도 뜨지 않습니다. 지금의 가상 앱과 같습니다.
