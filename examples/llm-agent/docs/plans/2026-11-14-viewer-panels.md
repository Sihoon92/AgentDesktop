# 뷰어 패널 배치 수정 계획

- 날짜: 2026-11-14
- 상태: 사용자 승인(2026-11-14, 시작 양식을 한 줄로 줄이는 제안 포함). 구현했고 헤드리스 Chrome 확인과 전체 테스트가 통과합니다. 실제 실행에서 답해 보는 확인(사용자)은 아직입니다.
- 대상: `examples/llm-agent/viewer/static/`(`index.html`, `style.css`, `app.js`, `chat.js`)와 그 테스트. 서버(`viewer/server.py`), 에이전트 코드(`agent/`), 기록 형식은 고치지 않습니다.

## 왜 고치는가

사용자가 실제 실행에서 겪은 문제 넷입니다(2026-11-14).

1. 왼쪽 실행 목록이 늘 240px을 차지합니다. 평소에는 볼 필요가 없습니다.
2. 오른쪽의 실행 요약과 대화가 340px 칸 하나를 위아래로 나눠 써서 둘 다 좁습니다.
3. 패널을 접거나 펼 수 없습니다.
4. 질문에 답할 수 없습니다. 실행 `20261114-042628`의 타임라인 7번 질문("…체크를 해제할까요?")에서 답 칸이 보이지 않았습니다.

### 4번의 원인 (재현해서 확인함)

답 기능은 없어지지 않았습니다. 서버는 답을 받을 수 있는 상태였고 답 양식도 만들어져 있었습니다. 양식이 **화면에서 눌려 잘렸습니다.**

대화 패널은 오른쪽 칸의 아래쪽에 있고, 그 안에서 대화 기록과 답 양식이 남은 높이를 나눠 줄어듭니다(`.chat-composer`가 `flex: 0 1 auto; min-height: 0; overflow: auto`). 같은 실행의 기록을 복사해 헤드리스 Chrome으로 띄워 잰 값입니다.

| 창 크기 | 답 양식에 필요한 높이 | 실제로 받은 높이 | 보이는 것 |
| --- | --- | --- | --- |
| 1920×950 | 188px | 148px | 입력 칸은 보이고 보내기 버튼이 잘림 |
| 1536×730 | 188px | 94px | 안내 글과 빠른 답 버튼만 보임. 입력 칸은 윗줄만, 보내기 버튼은 안 보임 |
| 1280×620 | 188px | 67px | 안내 글만 보임 |

양식 상자 안에서 스크롤하면 입력 칸이 나오지만 스크롤 막대가 눈에 띄지 않습니다. 예전에 답할 수 있었던 것은 위쪽 내용이 적었기 때문입니다. 그 뒤 시작 양식에 시스템 칸이 생겨 두 줄이 됐고(100px), 오른쪽 칸에 실행 요약 상자가 생겼고, 이번 질문은 후보가 둘이라 양식에 빠른 답 버튼 줄이 더해졌습니다.

재현은 기록 폴더의 복사본을 답할 수 있는 실행처럼 띄우는 임시 서버와, 창 크기별로 양식의 위치를 재는 스크립트로 했습니다(저장소에는 넣지 않음).

## 고칠 것

### 1. 배치

```
지금:   [ 실행 목록 240 ] [ 캡처            ] [ 요약 + 단계 정보 ]
                                              [ 대화 + 답 양식   ]  340

바꾼 뒤: [▸] [ 대화          ] [ 캡처        ] [ 요약 + 단계 정보 ]
         36  [ 답 양식(바닥) ]                   360
              380
```

- **실행 목록:** 처음에는 접혀 있습니다. 접힌 모습은 36px 폭의 세로 띠이고 펴는 버튼 하나가 있습니다. 펴면 지금의 목록(검색, 상태, 날짜, 별표)이 그대로 나옵니다. 고른 실행이 없을 때(처음 열었고 기록이 있을 때)는 펴진 채로 시작합니다.
- **대화:** 캡처의 왼쪽 칸으로 옮깁니다. 칸의 높이를 모두 씁니다. 위는 대화 기록, 바닥은 답 양식입니다.
- **단계 정보:** 오른쪽 칸에 실행 요약, 단계 정보, 모델이 받은 관찰 글만 남습니다. 대화가 빠져서 칸의 높이를 모두 씁니다.
- **시작 양식(지시, 실행 파일, 시스템, 권한):** 지시 칸과 실행 버튼만 한 줄로 두고, 나머지 칸은 "설정" 버튼으로 펴고 접습니다. 지금 두 줄(100px)이 한 줄(약 55px)이 됩니다. *사용자가 말한 것은 아니고 세로 공간을 위한 제안입니다.*

### 2. 모든 패널을 접고 펴기

- 실행 목록, 대화, 단계 정보 세 패널의 제목 줄에 접기 버튼을 둡니다. 접으면 36px 띠가 되고 캡처가 그만큼 넓어집니다.
- 접힌 띠에는 패널 이름과 펴기 버튼이 있습니다. 버튼은 키보드로 누를 수 있고 `aria-expanded`를 가집니다.
- 접은 상태는 브라우저에 저장해(`localStorage`) 새로고침하거나 뷰어를 다시 켜도 유지됩니다. 저장소를 쓸 수 없으면 기본값으로 시작합니다.
- **질문이 대기 중일 때:** 대화 패널이 접혀 있으면 자동으로 폅니다(질문 하나에 한 번). 그 뒤 사용자가 다시 접으면 접힌 띠에 "질문 대기" 표시가 남습니다. 답하지 않으면 실행이 멈추므로 질문을 놓치지 않게 하는 것이 접은 상태를 지키는 것보다 우선입니다.

### 3. 답 양식이 눌리지 않게

- 답 양식은 줄어들지 않습니다(`flex: none`). 높이가 모자라면 대화 기록이 줄어들고 기록 안에서 스크롤합니다.
- 창이 아주 낮아 기록의 최소 높이와 양식을 함께 담지 못하면 대화 칸 전체가 스크롤됩니다. 이때도 양식 안쪽의 숨은 스크롤은 생기지 않습니다.
- 등록 승인 양식처럼 항목이 많아 긴 양식은 양식 자체가 칸 높이의 일부(예: 70%)까지만 차지하고, 보내기 버튼 줄은 양식 바닥에 고정합니다. 어떤 길이에서도 보내기 버튼이 보입니다.
- 질문이 생기면 대화 기록을 끝으로 스크롤하고 입력 칸에 포커스를 줍니다(사용자가 다른 입력 칸에 글을 쓰는 중이면 포커스를 옮기지 않습니다).

### 4. 좁은 창

- 1100px 이하: 지금처럼 세로로 쌓되 순서를 대화 → 캡처 → 단계 정보로 합니다. 대기 중인 질문의 답 양식이 캡처보다 먼저 나옵니다.
- 내보낸 HTML(`view.py --export`): 실행 목록과 시작 양식은 지금처럼 숨기고, 대화와 단계 정보의 접기는 그대로 동작합니다. 답 양식은 원래 나오지 않습니다.

## 하지 않는 것

- 패널 폭을 끌어서 조절하기. 고정 폭(대화 380px, 단계 정보 360px)과 접기로 먼저 써 보고, 모자라면 따로 합니다.
- 지식 화면의 배치 변경.
- 서버 API, 기록 형식, 답을 받는 흐름의 변경.
- 같은 PC에서 답하는 동안 대상 앱의 목록이 닫히는 문제와 포커스 문제. 뷰어 배치로 풀리지 않으며 따로 다룹니다.

- `examples/llm-agent/README.md`의 뷰어 설명(오케스트레이터).

## 작업과 검증

| 순서 | 누가 | 무엇 |
| --- | --- | --- |
| 1 | w2 | `index.html`, `style.css`, `app.js`, `chat.js`의 변경과 `tests/test_export.py` |
| 2 | w2 | 헤드리스 Chrome 확인(아래 기준). 창을 띄우지 않고 실제 모델도 부르지 않음 |
| 3 | 오케스트레이터 | 코드와 화면 그림 검토, 전체 테스트 재실행, README |
| 4 | 사용자 | 실제 실행에서 질문에 답해 보기 |

끝났다고 보는 기준:

- 답할 질문이 있는 실행을 1920×950, 1536×730, 1280×620, 1000×700에서 열었을 때 입력 칸과 보내기 버튼이 **스크롤 없이** 창 안에 모두 보입니다(확인, 막힘, 완료 확인, 등록 승인 네 종류의 질문 모두). 고치기 전의 코드에서는 이 확인이 실패해야 합니다.
- 세 패널을 각각 접고 펼 수 있고, 새로고침해도 상태가 유지됩니다. 모두 접으면 캡처가 그만큼 넓어집니다.
- 대화 패널을 접은 채 질문이 오면 패널이 펴집니다.
- 답을 보내면 서버에 한 번 전달되고 대화에 "내 답"이 보입니다(기존 동작).
- 라이트와 다크, 내보낸 HTML에서 가로 스크롤이 생기지 않습니다.
- `python -m pytest -q` 전체 통과.

## 구현하면서 정한 것

- 창 폭이 1400px 이하이면 대화 340px, 단계 정보 320px로 줄입니다(넘으면 380px, 360px). 1280px 창에서 캡처가 너무 좁아지지 않게 하려는 것입니다.
- 1100px 이하의 세로 배치에서는 페이지 전체가 아니라 배치 영역 안에서 스크롤하고, 대화 칸의 높이를 그 영역의 높이로 제한합니다. 그래야 답 양식이 스크롤 없이 보입니다.
- 실행 목록은 주소에 실행이 지정되지 않았으면 펴서 시작합니다(기록이 없을 때도). 사용자가 접거나 편 적이 있으면 그 선택을 따릅니다.
- 질문 때문에 대화가 펴져도 저장된 선택은 바꾸지 않습니다. 접힌 띠의 "질문 대기" 표시는 터미널에서 답하는 실행에도 보이고, 자동으로 펴는 것은 이 뷰어에서 답할 수 있을 때뿐입니다.
- 접힌 시작 양식 옆에 지금 설정(실행 파일 이름, 시스템, 권한, 동작 전 승인)을 요약으로 보여 줍니다.
- 답 입력 칸에서 Esc를 누르면 포커스가 빠져 ← → 단축키를 쓸 수 있습니다.
- 재현 때 본 503은 지식 폴더를 주지 않은 임시 서버의 `GET /api/knowledge`였고, `view.py`로 띄운 뷰어에서는 생기지 않습니다.

## 확인이 필요한 것

- 시작 양식을 한 줄로 줄이는 제안(위 1번의 마지막 항목)을 넣을지.
- 대화 380px, 단계 정보 360px의 폭이 적당한지. 구현 뒤 화면 그림으로 다시 확인받습니다.
